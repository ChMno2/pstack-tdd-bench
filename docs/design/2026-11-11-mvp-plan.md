# pstack-tdd-bench MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 GitHub Actions 的固定容器中，對一個冒煙任務以 C1 與 C2a 各跑一次執行，產出軌跡、測試紀錄、run.json 與可重跑一致的 score.json。

**Architecture:** `bench` 是一個 Python 套件，分成四塊：任務與快照（task、snapshot）、側錄（testlog 外掛、watch）、執行（conditions、fingerprint、runner、trajectory）、評分（scoring/*）。執行器以子行程呼叫固定版本的 Claude Code CLI，側錄與評分都不依賴 harness。GitHub Actions 只負責把這些東西放進以 digest 固定的容器裡跑。

**Tech Stack:** Python 3.12、pytest 8.3.3、pytest-cov 5.0.0、mutmut 3.8.1、PyYAML、Claude Code CLI 2.1.322、Docker、GitHub Actions、uv（本機開發）。

**Spec:** [docs/design/2026-11-11-design.md](2026-11-11-design.md)，名詞見 [GLOSSARY.md](../../GLOSSARY.md)，決策見 [docs/adr/](../adr/)。

> 2026-11-11 執行完畢後專案結構重整：`bench/` 分成 `task/`、`harness/`、`capture/`、`scoring/`，測試照同樣分類，文件移到 `docs/guides/` 與 `docs/design/`。本計畫內的檔案路徑是執行當時的路徑，現行路徑見 README 的「專案結構」。

## Global Constraints

- Python 3.12（LIMS 要求 `>=3.12,<3.14`）。本機用 `uv venv --python 3.12`。
- LIMS 固定 commit：`227be16e3365e9956da0dec8efa987db3e0f3e4f`，以 git submodule 放在 `sut/lims`。
- pstack 固定 commit：`c742dd61706fbacc1b95f1a20b7b988cf096ce6c`，複製 `harness/pstack/claude-code/` 到 `vendor/pstack/`，內容不得修改。
- Claude Code CLI 版本：`2.1.322`。執行環境必設 `DISABLE_UPDATES=1`、`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`。禁止 `--bare`。
- 模型 ID：`claude-sonnet-5-5`，主 Agent 與所有子 Agent 都用它（`CLAUDE_CODE_SUBAGENT_MODEL` 加 `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`）。
- 認證：同一次執行的環境中，`CLAUDE_CODE_OAUTH_TOKEN` 與 `ANTHROPIC_API_KEY` 只能存在一個，否則拒絕啟動。
- 停用工具：`WebFetch,WebSearch,AskUserQuestion`。
- 自動回覆文字：`請依你的判斷繼續，不要再詢問`，上限 3 次。
- 重複次數 3，不穩定測試重跑次數 3。
- 評分環境：`TZ=UTC`、`PYTHONHASHSEED=0`。
- Agent 以非 root 使用者 `agent` 執行，讀不到 bench 的 checkout、`tasks/` 與參考實作。
- 完成宣稱只記錄，任何評分函式都不得讀取它。
- GitHub Actions：`runs-on: ubuntu-24.04`，只用 `workflow_dispatch` 觸發，容器與 service 一律以 `@sha256:` digest 指定。

## Review Focus

1. Agent 把新測試寫進既有的測試檔：仍要算成新增測試。由 Task 10 的 `test_added_test_in_existing_file_counts_as_added` 鎖住。
2. Agent 從頭到尾沒跑過 pytest：遵循度為 false，評分不能當掉。由 Task 12 的 `test_empty_testlog_is_not_followed` 鎖住。
3. CLI 非零結束、撞到用量上限或逾時：run.json 標記狀態，評分照常產出。由 Task 9 的 `test_nonzero_exit_marks_harness_error` 與 Task 14 的 `test_score_runs_for_failed_run` 鎖住。
4. 新功能任務的新測試在起始快照上收集失敗（import 不存在的模組）：算紅燈。由 Task 11 的 `test_collection_error_counts_as_red` 鎖住。
5. Agent 上網抓公開的 LIMS 原始碼：該次執行標記為受污染。由 Task 14 的 `test_lims_fetch_marks_contaminated` 鎖住。
